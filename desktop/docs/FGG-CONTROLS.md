# NANO68 原厂协议接入

本次目标是 [FGG 官网](https://fgg.com.cn/fgg/about)所述的 NANO68 系列，官网使用 MADLIONS 名称。软件内部品牌为 `fgg`，显示为“美加狮 FGG”；不把它并入 madcatz.com 的 RAT 鼠标目录。

## 型号边界

原厂旧 [HUB](https://hub.fgg.com.cn/) 的型号注册表把以下正常 USB 身份交给同一个 `Fire` 控制器。每个身份保留独立型号记录，展示层将同名版本合并为四张产品卡，仍可选择轴体版本。

| 产品 | VID | 正常 PID | 接口 |
| --- | --- | --- | --- |
| NANO68 | 373B | 1064 | Usage Page 0001 / Usage 0000 |
| NANO68 Pro | 373B | 106B、106D、10FF、1100、113A、110C、1143 | 同上 |
| NANO68 Plus | 373B | 1101 | 同上 |
| NANO68 Ultra | 373B | 11A1 | 同上 |

LL 系列的 `FF60:0061` 接口使用另一个控制器，V2 HUB 的 `28E9 / FF87:0020` 也采用另一套协议。它们以及 Bootloader 身份均不匹配本适配器。不同 PID 不凭产品名称互相替代。

## 已接入的统一控件

- 24 个原厂主灯效果，包括关闭；亮度 0–100、动态速度 0–4、单色 RGB。
- 1000 / 2000 / 4000 / 8000 Hz 回报率，以及 Win 键锁。
- NANO68、Pro、Plus：单键触发点、RT 按下/释放灵敏度、连续 RT。
- 四款：单键顶部/底部死区，0–1 mm，步进 0.02 mm。

控制器只在连接成功并读到当前值后返回能力。单色和速度对不适用的灯效给出明确提示，不悄悄切换灯效。默认按键矩阵由设备读取，按键选择使用它返回的真实索引；本轮未写宏、改键、校准、固件升级、轴体切换或配置槽切换。

基础 NANO68 的触发/RT 步进为 0.02 mm，Pro、Plus 为 0.01 mm，触发点下限 0.1 mm，RT 下限等于各自步进。每键行程上限根据读回的轴体类型查原厂表：1=4.0 mm；2/3/5=3.3 mm；4=3.7 mm；6–14=3.4 mm。界面范围取本次实际轴体范围的交集，写入前再次检查目标键当前轴体，保留高位轴体/优先级标志。

旧 HUB 的 `xl` 范围表没有 NANO68 Ultra 的触发/RT 步进条目，因此 Ultra 本轮不开这两个控件；已有的灯效、回报率、Win 锁和死区正常开放。不用 Pro 的参数猜 Ultra。

## 报文证据

原厂源码取自以下三个文件，原包与解码副本存于用户缓存 `vendor-resources/fgg/source`。解码脚本只在独立 VM 中计算字符串数组及解码函数，不执行原厂应用、安装器或设备代码。

1. [`index-D9yt26aK.js`](https://hub.fgg.com.cn/assets/index-D9yt26aK.js)：型号表、`Cr`、`Sr`、`FunctionVariableArea`、`KeyTriggerTravelActionV2`、`Fire`。
2. [`ConfigPage-W6m-4pvW.js`](https://hub.fgg.com.cn/assets/ConfigPage-W6m-4pvW.js)：灯效速度反向、回报率编码、触发/RT 单位、`xl` 步进、死区编辑器。
3. [`vue-draggable-plus-dU8dfF6a.js`](https://hub.fgg.com.cn/assets/vue-draggable-plus-dU8dfF6a.js)：`Pn` 灯效、`Nn` 轴体最大行程、`Ln` 型号分组。摘录见 `catalog/fgg-controls.json`。

旧 HUB 用 `sendReport(0, payload)`，payload 固定 64 字节。偏移 0=`55`，1=命令，2=key，3=校验和，4=有效数据长度，5–6=小端地址，8–63=数据。原 `Cr.toUint8Array` 对首次序列化的 3–63 求和，校验位初始为零，等价于本实现对 4–63 求和后取低八位。输入 `AA` 响应按命令匹配；原厂不要求 ACK 回显地址，本实现不要求写 ACK 回显地址/长度，随后必须读取当前设置。读响应的地址 0 视为未回显，非零且与请求冲突则忽略。请求串行，超时后整个连接停止，避免迟到响应被后续请求使用。

读取长度按实际源码分开处理：`FunctionVariableArea` 只用固定字段偏移，允许长度字段 0 或 56；`KeyMatrix.buffer` 和 `KeyTriggerTravel.buffer` 则明确使用响应 byte4 切片，`Fire` 用实际返回长度推进地址。因此分块读取要求非零且不超过本次请求长度，并按实际长度继续，不能按请求块长跳过。上述依据见解码格式化文件的 12963、13152、13539、13948 行；没有把假设备中地址必然回显的行为当作固件要求。

| 命令 | 数据与地址 |
| --- | --- |
| 03 / 04 | 固件版本 / 当前配置索引、配置数量 |
| 05 / 06 | 读写 56 字节功能区，地址 `configIndex × 0x40` |
| 07 | 默认按键矩阵，384 字节，分块 55，地址 `configIndex × 0x800` |
| A0 / A1 | 触发数据，128 × 8 字节，地址 `configIndex × 0x400 + keyIndex × 8` |
| 01 / 02 | 原厂磁轴写入前后的快速通信开始/结束 |

功能区偏移均相对 payload：4 低四位为回报率（1=8K、2=4K、3=2K、4=1K），高四位扫描率保持不变；6 bit0 为 Win 锁，其余锁位保留；8 效果、9 亮度、10 速度，速度显示值为 `4 - raw`；12 为全彩标志，14–16 为 RGB。写单色时清全彩标志，保留侧灯 24–31 以及所有无关/保留字节。

单键 8 字节格式：byte0 低五位轴体；byte1 低四位触发类型（0=关闭、1=RT、2=连续 RT）；word2 低九位触发点；word4 低九位按下 RT、高七位底部死区；word6 低九位释放 RT、高七位顶部死区。触发/RT 显示为 `(raw + 1) / 100` mm；死区为 `raw / 100` mm，不加一。采用读、修改目标字段、写、再读回的流程，不清空邻键或未开放功能。

## 验证与连接生命周期

`node --test test/fgg-provider.test.cjs test/fgg-wire-vectors.test.cjs` 共 31 项通过。使用纯内存 HID 夹具及独立执行原厂 `Cr`/`FunctionVariableArea` 得到的报文向量，覆盖全部十个精确身份、原生报文、位域保留、非零配置槽、单键修改及回读不一致。额外检查取消授权、延迟 open、超时后清理、同步关闭后不再发送、已被其他连接打开的设备不被关闭，以及零地址/零长度写 ACK、固定字段读无长度回显、冲突地址和变长分块读取。

所有型号仍标记“待验证”。模拟设备和原厂源码对照证明编码与页面流程，不能替代 NANO68 真机验证。本轮没有向用户硬件写设置，也没有执行原厂安装程序。
